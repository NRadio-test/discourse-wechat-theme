# Discourse 微信式会话主题

每个话题就是一个群聊。把群聊里混在一起的“99+”消息分成有明确主题的讨论：手机打开话题会话列表，进入后在底部直接输入、发送；电脑采用左侧会话列表、右侧讨论内容的布局。

这是一个公开协作开发中的 Discourse **主题组件**。微信式操作习惯是主要设计参考，抖音式的轻量点赞与分享是次要参考；本项目与微信、抖音及其所属公司没有关联。

## 当前能力 · 1.2.2

- 手机单列列表与聊天页，电脑双栏布局。
- “十大 / 全部 / 精华”三个入口；十大最多显示十条真实日榜话题。
- 消息气泡、昵称优先显示和简洁的回复引用条。
- 普通话题底部直接发送文字、表情和图片，不打开论坛的浮动回复编辑器。
- 手机 Enter 换行；电脑 Enter 发送、Shift+Enter 换行；中文输入法组合期间不提交。
- 当前浏览器内按用户、话题隔离文字草稿；发送中防重复提交，失败保留输入，审核入队显示提示。
- 极简发起话题：填写话题名，按需添加开场内容和图片；普通用户不需要选择板块或标签。关闭后再打开可继续草稿。
- 消息操作收进菜单，支持长按、桌面右键和按钮入口；复用原生回复、点赞、收藏、分享及管理操作，并提供正文复制与独立选字模式。
- 首帖与回复统一为紧凑聊天气泡；顶部「•••」可回到开头、跳到最新和分享话题。
- 精简头像资料卡，突出头像、昵称和资料入口，保留隐私状态与必要管理功能。
- 沿用 Discourse 的权限、点赞、附件、举报和管理能力。

话题内“热评十大”、管理员评论加精、年度互动榜和点踩尚未实现。完整范围与验收标准见 [产品需求](docs/PRODUCT-REQUIREMENTS.md)。

1.2.1 针对手机长按时消息菜单、系统选字与论坛引用菜单叠加的问题，改为触摸默认只打开消息菜单，需要选字时点击“选择文字”。首帖不再显示大卡片，移除逐条重复时间、自己的昵称及楼层浮标，修复裸链接的白色底块，并缩小头像资料卡。

1.2.2 针对安卓微信仍残留选字手柄的反馈，补充触摸选区建立拦截、延迟选区和空选区清理；复制成功后关闭菜单，失败时保留“选择文字”入口。真实微信设备仍需复验。

前端行为测试覆盖回复、消息菜单及创建话题；实际编译和浏览器验证范围见 [开发指南](docs/DEVELOPMENT.md#回归测试)。此前 1.2.0 已在隔离纯核心环境通过 6 项真实 Discourse 发帖接口回归。模拟视口不能代替真实微信内核的手势与软键盘验证。

## 兼容性与边界

目前依据 **Discourse 2026.7.3** 的接口开发，使用 `DockedComposer`、主题 outlet 和原生帖子模型。其他版本需要单独验证；不能把“可安装”视作“全部功能兼容”。

普通新话题使用极简表单；编辑已有帖子、私信和管理员专用操作仍可使用原生界面。登录与身份认证由站点提供，本仓库不包含认证服务、店铺登录插件或密钥。

文字草稿仅保存在当前浏览器，不跨设备同步；待发送附件不保证跨刷新恢复。软键盘避让已有实现，但真实手机、微信内置浏览器和不同输入法仍需要设备验证。

## 安装

1. 先在测试站点的主题管理页面中选择从 Git 仓库安装，仓库地址为 `https://github.com/NRadio-test/discourse-wechat-theme`。
2. 将组件关联到一个正常工作的基础主题，先预览，再启用。
3. 在组件设置中填写社区名称、精华入口及欢迎文案。精华入口应指向该站点真实存在的标签页面，不能照搬其他站点的标签 ID。
4. 验证登录、普通回复、中文输入、图片上传、草稿恢复和管理员操作。生产站点建议固定到已验收的提交或发布标签。

组件设置定义以 [`settings.yml`](settings.yml) 为准；配置要求见 [开发指南](docs/DEVELOPMENT.md#站点配置)。精选可以由内部标签承载，普通用户不需要看到标签或分类。相关使用权限由 Discourse 后台配置，主题不会代替权限控制。

主题不会自动修改服务端设置。要支持“两字话题名、一字消息”的短聊天，需要在站点后台设置 `min_topic_title_length = 2`、`min_first_post_length = 1`、`min_post_length = 1`。首帖输入速度自动禁言规则应根据社区场景评估，详见开发指南；权限、审核和其他限流仍由 Discourse 执行。

回退时，在基础主题的组件列表中解除本组件关联，恢复原来的组合。无需删除话题、用户或恢复业务数据库。
