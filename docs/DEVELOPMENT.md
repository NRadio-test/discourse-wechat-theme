# 开发指南

## 仓库结构

仓库根目录就是 Discourse 主题组件目录，可由主题管理器安装。

```text
about.json
settings.yml
common/
  shell.scss
  chat.scss
  inline-chat.scss
  message-actions.scss
  topic-groups.scss
  profile-card.scss
  common.scss
javascripts/discourse/api-initializers/wechat.gjs
javascripts/discourse/api-initializers/topic-groups.gjs
javascripts/discourse/api-initializers/profile-card.gjs
scripts/build-css.mjs
tests/inline-reply.test.mjs
tests/message-actions.test.mjs
tests/topic-groups.test.mjs
tests/server/
docs/
```

`common/common.scss` 是发布用生成文件，按 `shell.scss`、`chat.scss`、`inline-chat.scss`、`message-actions.scss`、`topic-groups.scss`、`profile-card.scss` 的顺序拼接。修改源文件后重新生成并一并提交，不要只修改生成文件。`node scripts/build-css.mjs --check` 只检查内容是否一致，不改写文件。

三个 initializer 均包含内联 `<template>`，必须以 `.gjs` 编译。将后缀改为 `.js` 会破坏编译。

## 本地准备

准备 Git、Node.js 22，以及一个可自由重置的 Discourse 测试站点。当前 1.2.1 主题的接口基线是 Discourse 2026.7.3；维护其他版本前应先确认 `DockedComposer`、outlet 和帖子模型接口。

```sh
git clone https://github.com/NRadio-test/discourse-wechat-theme.git
cd discourse-wechat-theme
node scripts/build-css.mjs
node --test tests/*.test.mjs
```

命令行行为测试不会启动真实 Ember 应用，不能证明主题模板能编译、DOM 手势正常或手机键盘兼容。安装预览和浏览器验收必须另做。

不要为测试向生产论坛提交公开样例帖，也不要把生产备份、账号资料或原始日志放进仓库。

## 站点配置

可配置项以根目录 `settings.yml` 的最终定义为准。公开版本应能适配不同站点，而不是依赖某个实例的数据 ID。

| 配置 | 用途 | 示例 |
| --- | --- | --- |
| `community_name` | 社区显示名称 | `示例社区` |
| `featured_tag_path` | 本站精华标签页面的路径 | 使用本站实际生成的标签路径 |
| `default_topic_category_id` | 创建话题使用的内部默认分类 | `0` 表示回落到 `siteSettings.default_composer_category` |
| `welcome_title` | 电脑未选中话题时的标题 | `选择一个话题，一起聊聊` |
| `welcome_description` | 欢迎区辅助文案 | `从左边进入讨论` |
| `footer_text` | 会话列表底部文案 | `分享经验，认识同好` |

路径类设置应限制为站内允许的路径，拒绝 `javascript:`、外站跳转及非法值。无法加载精华数据时要显示真实错误或空状态，不能偷偷换成普通话题列表。

标签的管理权限、昵称数据、登录方式、默认分类和发帖审核均在 Discourse 后台配置。默认分类和运营精选标签是内部配置，普通用户侧不展示板块或标签选择。不要把认证参数或密钥添加为可下发到浏览器的主题设置。

欢迎区的默认标题与描述均可通过设置调整。创建话题使用的默认分类必须真实存在且允许当前用户发帖；配置错误应明确报错并保留输入，不得悄悄改投其他分类。

主题不会自动修改服务端设置。若站点采用“两字话题名、一字消息”的聊天规则，应在 Discourse 后台单独设置：

| 服务端设置 | 短聊天配置 | 作用 |
| --- | --- | --- |
| `min_topic_title_length` | `2` | 允许两字话题名 |
| `min_first_post_length` | `1` | 允许短开场内容 |
| `min_post_length` | `1` | 允许短回复，也满足初步与排队校验 |

`auto_silence_fast_typers_on_first_post` 需要按站点场景评估：很短的中文首帖或以话题名直接开聊，可能触发仅按输入速度判断的误禁言。1.2.0 的验证实例因该误判关闭了这一项；这不是主题默认设置，也不代表所有社区都应关闭。其他权限、审核与限流继续由 Discourse 处理。主题记录实际输入活动，不为通过检查编造或延长输入时长。

## 前端结构

- 会话列表：使用原生话题列表数据、分页和路由，限制日榜最多展示十条。
- 话题正文：沿用 Discourse 的帖子流，不复制出一套脱离原生权限和阅读进度的数据模型。
- 底部输入：复用 Discourse 的 `DockedComposer`，通过原生帖子模型提交。
- 普通回复接管：主题拦截适用话题的回复入口；编辑、私信和特殊管理流程保持明确边界。
- 消息操作：包装原生帖子菜单，提供长按、右键和替代按钮入口；动作及权限沿用核心，菜单不可用时保留可访问的原生入口。
- 选字模式：触摸默认禁止气泡选字，显式选择文字时恢复当前气泡的原生选择；论坛引用工具条在这两种触摸路径下都不出现，桌面选字仍可使用原生引用。
- 资料卡：`profile-card.gjs` 在核心卡片 outlet 内提供查看资料、关闭；样式缩小头像并隐藏普通用户不需要的统计、徽章和按作者筛选入口。隐私/账号状态、取消筛选和管理操作保留。
- 阅读导航：顶部「•••」提供开头和最新消息；隐藏的是原生楼层浮标，不改变阅读进度数据。
- 创建话题：`topic-groups.gjs` 提供话题名、可选开场内容和图片。分类使用后台默认值，标签不进入普通用户表单；无内容或附件时用话题名作为首帖。1.2.0 已实现，真机验收范围见下文。
- 原生新建拦截仅限会话界面；后台和独立分类页面保留原生创建上下文，避免把私有分类的创建操作悄悄改成公开讨论。

优先使用稳定的 theme API、outlet 和组件接口。修改内部类或依赖选择器时，说明理由、适配版本和升级后的验证方法。不要为了隐藏复杂界面而全局移除管理入口。

## 发送与草稿约束

修改这部分代码时，应保留以下行为：

1. 同一用户、同一话题只有一个进行中的发送请求；输入框重新挂载不能解除这个锁。
2. 只有服务端确认成功或进入审核队列，才能清理这次提交的内容。
3. 草稿按用户和话题隔离。旧请求返回时不能清掉后来写的新草稿。
4. 已销毁输入框不能再触发核心组件清稿，影响新的输入框。
5. 服务端已接受后，刷新帖子流失败只能提示刷新，不能诱导重复发送。
6. 发送期间阻止会改变提交内容的输入、文件粘贴、拖放和上传操作。
7. 中文组合输入不提交；手机 Enter 换行，电脑 Enter 发送、Shift+Enter 换行。

当前文字草稿使用浏览器存储，不具备跨设备同步或可靠的附件恢复。新增云端草稿时，应独立设计原生草稿格式、版本冲突和权限规则，不能简单共用一个字符串键。

## 回归测试

运行全部前端行为回归：

```sh
node scripts/build-css.mjs --check
node --test tests/*.test.mjs
```

1.2.3 共 69 项：回复 12 项、菜单 39 项、创建话题 12 项、消息编辑 6 项。覆盖重复提交、切换话题、草稿与附件保留、输入法、权限边界、触摸选区、长按松手、原生按钮、编辑加载与保存失败、异步回调及销毁。

普通消息编辑通过核心的 `topic:edit-post` 事件接入；校验话题、消息类型及 `can_edit` 后标记已处理。编辑原文从 `/posts/:id.json` 读取，经同一路径 PUT 保存，服务器仍校验编辑权限。不要先改流中模型再请求服务器；仅成功响应后更新显示。原回复 DockedComposer 保持挂载并隐藏，以保留回复草稿和已上传附件。编辑正文保留 Markdown，当前不在编辑面板提供新附件上传；取消会放弃本次修改。特殊消息和本地化译文编辑仍交由核心处理。

从 `post-menu-buttons` 的 DAG 中移除 COPY_LINK、BOOKMARK、SHARE，避免生成相关按钮及收藏提醒流程。即时按钮的菜单收起监听在捕获阶段注册，下一帧关闭；不要阻断核心动作，也不要依赖其 click 冒泡（DButton 可能停止传播）。触摸松手只在已完成长按且仍处于抑制窗口时取消默认行为，不能取消短按或滚动。

触摸手势及菜单显示期间，使用 `selectstart` 阻止消息正文和操作菜单的原生选区建立，并用临时 `selectionchange` 监听器清理晚到的本消息选区。清理不能只判断选中文本非空：折叠选区和空白选区也可能留下手柄。范围限定在当前气泡与菜单，排除可编辑控件；显式“选择文字”、桌面选字、外部选区不清理。不拦截 `touchstart` 或滚动，不全局禁用文本选择。复制成功关闭菜单，失败保留重试入口；异步回调通过菜单版本标记避免干扰后来打开的菜单或选字模式。

核心会重新渲染帖子的完整 `class` 属性。消息模式使用独立 `data-wx-*` 属性保存状态，不能把 `classList.add()` 的结果当成持久标记。销毁时删除主题自己的属性及监听器，不修改核心类名。

测试读取本仓库的真实主题方法，通过最小协作对象检验状态与调用约定。回复测试默认使用独立编写的最小 Composer 适配器，它只表达提交、清稿和键盘行为约定，**不是 Discourse 核心组件实现**。这些回归可以验证主题状态逻辑，但不能证明核心接口、Glimmer 编译、上传或实际 DOM 行为兼容。

如果本地已有对应版本的 Discourse 源码，可以额外运行兼容模式，按该源码执行真实核心组件方法：

```sh
DISCOURSE_SOURCE=/path/to/discourse node --test tests/inline-reply.test.mjs
```

此路径是用户自己的源码 checkout，不会被复制进本仓库。兼容模式同样没有启动 Ember，仍需实际页面验证。不要在测试里复制一份主题发送实现，也不要把未经来源与许可审查的上游组件整份放进仓库。

真实服务端回归见 [`tests/server/README.md`](../tests/server/README.md)，必须在隔离的 `RAILS_ENV=test` 环境执行，不使用生产数据库。1.2.0 已在 Discourse 2026.7.3 使用 `LOAD_PLUGINS=0` 的纯核心环境通过 6 项发帖请求测试，覆盖短标题、待审核、私有与只读分类、匿名拒绝和内容长度校验，不依赖专用认证插件。

GitHub Actions 在 `pull_request` 和 `main` 分支推送时使用 Node.js 22 检查生成 CSS 和行为测试。工作流只有 `contents: read` 权限，不接收部署凭据，也不自动发布或修改生产站点。

## 预览、发布与回退

先把提交安装到测试站点或独立预览组件，检查 SCSS 和 JavaScript 的编译诊断，再打开实际页面检查控制台及交互。仅看到主题记录保存成功不足以证明 JavaScript 编译成功。

发布前同步版本号、生成 CSS、需求状态及变更说明。确认无调试日志、真实用户数据和部署专用路径后，再由维护者发布标签。

回退采用主题组件关联或已验收的历史版本，不通过删除业务数据完成。公开仓库不要携带实例专用的自动激活脚本。

## 1.3.0 个人页接入与检查范围

`simple-account.gjs` 负责个人菜单、个人页导航和精简摘要。复用核心用户路由的授权与隐私检查，不直接请求或渲染其他用户的私有设置。`wechat.gjs` 将 `/u/:username/...` 纳入外壳，但不能把 `user` 作为话题列表筛选值；切换个人页时保留当前列表筛选。

草稿/收藏路由仅重定向，不调用删除接口、不清理服务器草稿、不关闭当前浏览器未发送内容恢复。资料隐藏或账号停用时不展示公开活动入口；待审核导航、安全页、用户屏蔽及管理控件保留。认证专属字段由认证插件处理，主题不修改登录协议。

核心菜单会缓存 Tab 对象。合并通知后需重排键盘导航位置，并在进入后台时恢复原始面板与位置，避免前台精简污染后台。测试包含切换前台→后台→前台的缓存对象复用。

普通用户入口检查矩阵：

| 路径/操作 | 本版处理 |
| --- | --- |
| 首页、话题、创建、回复、普通消息编辑 | 继续使用话题群和底部输入体验 |
| 长按/右键、正文选字 | 简洁菜单；无收藏/链接复制和论坛引用工具条 |
| 头像卡片、头像菜单、资料/活动页 | 简洁资料、话题/回复入口；去掉统计和徽章导航 |
| 草稿与收藏旧链接 | 返回全部话题，不删除已有数据 |
| 通知 | 合并常用提醒，保留已读、私信和审核入口 |
| 设置 | 收起不常用导航，保留账号、安全、通知、屏蔽 |
| 举报、删除确认、受限账号提示 | 核心权限与确认流程保留 |
| 私信创建、特殊内容编辑、管理后台 | 保留核心流程，后续独立设计，不用公共话题表单替代 |

新增 8 项个人页行为测试，总计 77 项。测试不访问生产数据；授权、页面渲染和样式还需在安装版本实际验证。
