# 产品需求与实现边界

本文件将早期讨论整理为可以开发、评审和验收的需求。它记录产品方向，不代表每项能力已经上线。状态发生变化时，应随对应 Pull Request 更新。

## 核心目标

做一个围绕话题组织的新型社区：**每个话题就是一个群聊**。解决大群“99+”消息里几条讨论线混在一起、后来的人接不上话的问题，又保留主题、历史、分享链接与管理能力。

**最重要的是微信式客户端体验。** 手机优先，尽量减少操作步骤和论坛术语。用户应能看到感兴趣的话题、直接输入、点击发送。电脑也要形成清晰、熟悉的会话体验，而不是把手机版简单放大。

抖音提供的参考主要是低成本互动：逐条内容点赞、分享，以及后续可能实现的热评展示。不要为了模仿界面而删除真实权限、审核、错误提示或无障碍支持。

最新产品要求明确：普通用户不需要板块或标签。用户从话题进入讨论，也直接创建话题，不承担论坛分类管理的负担。

## 信息结构

| 入口 | 用户希望看到的内容 | 当前状态 |
| --- | --- | --- |
| 十大 | 今天值得围观的热门话题，最多十条 | 已实现，使用 Discourse 原生日榜 |
| 全部 | 全部可见话题，继续加载更多 | 已实现，使用原生最新话题列表 |
| 精华 | 运营整理的长期优质话题 | 已实现入口，可以由内部标签承载；普通用户不见标签 |
| 发起话题 | 简单、明显的“＋”入口；填写话题名，按需添加开场内容 | 1.2.0 已实现；桌面与行为测试已验证，真机待验收 |

“十大”当前采用 Discourse 的 `period=daily` 数据。它不承诺按当地自然日零点重置，也不是自定义的实时热度算法。不足十条时显示实际数量，不用虚构数据或普通话题填满。

精华话题与精华评论是不同功能：前者可以通过话题标签实现，后者需要单独的持久化数据、管理权限和接口。

## 创建话题

创建入口像开始一场新的主题群聊。普通用户填写必需的话题名，按需添加开场内容和图片；不显示板块选择、标签选择或一排高级论坛字段。没有开场内容和附件时，使用话题名作为首帖。提交成功后直接进入这个话题的聊天页；进入审核队列时明确提示等待审核。

底层若需要分类，可使用站点配置的默认分类，由后台处理。运营仍可在后台维护内部标签与权限，但不能把这些字段重新暴露到普通用户的创建流程。

1.2.0 已实现极简创建、输入校验、图片上传、草稿关闭后恢复、发送防重和审核提示。创建行为测试与真实核心接口回归已通过，桌面已验证表单与草稿恢复；真实手机的完整创建流程仍待验收。

主题不会修改服务端的内容长度规则。短聊天目标需要站点设置最短标题 2 字、首帖 1 字、回复 1 字。首帖输入速度自动禁言规则可能误判短中文内容，由站点按使用场景选择；不能通过伪造输入时长绕过。具体设置见 [开发指南](DEVELOPMENT.md#站点配置)。

早期“多板块分类”的规划已不采用；已有分类仅用于存量数据与后台兼容，不是用户侧导航要求。

公开浏览是否允许、是否审核新用户和哪些人能发帖，由各站点自行配置。主题不得因为“界面像群聊”而跳过这些规则。

## 待实现的互动能力

### 话题内热评

用户应能快速查看一个话题中最受认可的回复，不必爬完所有楼层。候选方案是点赞数排序或“热评十大”。正式实现前需确定：

- 是按总点赞、近期点赞，还是带时间衰减的分数排序。
- 并列、已删除、被隐藏、无权限查看的回复如何处理。
- 是否覆盖全部回复，以及分页和实时更新如何工作。

只排序当前浏览器已经加载的几条回复，不能称为全话题热评榜。

### 管理员评论加精

运营或授权版主可以标记高质量评论，并在话题内单独查看。需要服务端保存加精状态、执行权限检查、记录操作并支持取消。前端隐藏按钮或 localStorage 标记不能替代这个能力。

### 年度互动榜

早期讨论提出“年度水王”和“年度点赞第一”等激励。榜单的统计窗口、有效行为、反刷规则和奖励由业务层确定。本主题不提供统计服务，也不宣称已实现这些榜单。

### 其他候选能力

- 喜欢之外的“不喜欢”表达：尚未确定产品规则，未实现。
- 更丰富的跨平台分享：目前保留原生单条消息分享入口；专用分享卡片和外部平台接入尚未实现。
- 搜索：不作为主界面的突出入口；仍需为有明确查找需求的用户保留可达方式。

这些参考需求不应推翻“先把聊天体验做顺”的优先级。

## 认证与实名信息的边界

早期业务讨论希望用户通过已有店铺或统一身份系统登录，减少多套账号并提高社区可管理性。主题只负责简洁的“登录”入口和已授权的公开资料展示。

手机号、外部平台 ID、账号绑定、实名验证和令牌交换属于独立认证系统，不进入主题仓库。公开昵称和头像不等同于实名身份；前端不能把用户的所有绑定标识公开展示，也不能把实名制当作无需审核的理由。

## 范围之外

- 认证服务、店铺后台和平台账号绑定。
- Cloudflare、容器、数据库、邮件及服务器运维。
- 公众号菜单、商店入口和外部群运营。
- 自定义排行榜后端、奖励系统、内容审核服务。

这些系统可以与论坛协作，但不应成为安装本主题的隐含前提。

- Discourse 2026.7.3 隔离纯核心环境的真实发帖接口回归 6 项通过，覆盖短标题、审核、长度校验与访问权限，不依赖专用登录插件。
- 运行站点 GJS 编译检查为零错误。
- 桌面浏览器验证了右键原生菜单、收藏子菜单、回复回到底部输入区、创建框无分类或标签，以及关闭再打开保留创建草稿。
- 直接访问 `/new-topic` 可在话题列表背景上打开简洁创建框；已检查 390×844 手机模拟视口下的创建面板。
- 欢迎区域采用“话题群”文案，不提供板块链接。

真实手机微信内的长按、滚动、选字、图片操作和软键盘尚未完成验收；不能把桌面或模拟视口结果写成真机通过。行为测试也不代替 Ember 渲染及实际上传、网络异常的浏览器验证。

至少覆盖桌面浏览器、手机窄屏及真实微信内置浏览器；区分已验证设备与模拟视口。测试应包含匿名用户、普通用户和管理角色，空列表、长标题、长消息、图片、失败重试、话题切换以及中文输入。

测试内容应放在测试站点或权限受控的测试话题。截图使用虚构资料，发布时不得带出真实手机号、用户标识或管理凭据。

## 1.2.1 手机反馈修正

真实手机反馈指出三项问题：长按时消息操作、系统选字和论坛引用同时出现；头像资料卡过大且信息杂乱；首帖、消息间距、链接底色与楼层浮标仍有明显论坛感。本版以这些问题为验收目标。

- 触摸长按进入消息菜单；点击“选择文字”才进入系统选字，退出后恢复聊天。桌面鼠标选字和链接菜单保留。
- 消息使用统一气泡布局，自己的消息靠右，不再给首帖特殊大卡片。
- 头像资料卡缩小，显示公开昵称；阅读统计、徽章和按作者筛选不占普通用户的卡片。
- 「回到开头 / 跳到最新 / 分享话题」集中在顶部更多菜单。

53 项行为测试、实际主题编译、手机模拟视口及桌面布局检查已通过；选字时消息菜单与论坛引用工具条均不显示。实际手机反馈不能用模拟视口结果替代，微信系统选字手柄和原生复制菜单仍需在真实设备复验。

## 1.2.2 安卓微信长按补充修正

手机截图显示消息菜单与绿色选字手柄仍可同时存在，复制后菜单也继续停留。补充选区建立拦截、菜单打开后的延迟选区清理及空选区清理；复制成功收起菜单，失败保留明确反馈和选字入口。“选择文字”仍是独立模式，允许系统手柄；完成或退出后清理本消息选区。不能破坏滚动、短按链接/图片、底部输入和桌面文本选择。59 项行为测试通过，实际 Android 微信手柄行为须真机复验。
